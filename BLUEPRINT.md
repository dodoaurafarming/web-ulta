Blueprint Pengembangan Web: Ular Tangga Multiplayer (ULTA/1.0)Bangun aplikasi web Ular Tangga Multiplayer Real-Time dari awal hingga siap deploy menggunakan React + Vite (TypeScript + Tailwind CSS) untuk frontend (target deploy: Vercel) dan Prisma + MySQL (target deploy: TiDB Cloud) untuk kebutuhan data persisten web. Seluruh logika permainan real-time dikendalikan oleh server TCP Python yang sudah ada di VPS (authoritative server) dan terhubung ke browser melalui jembatan WebSocket (WebSocket Bridge).   1. Arsitektur Sistem & Tech StackFrontend Web: React + Vite + TypeScript + Tailwind CSS (siap deploy di Vercel, sertakan vercel.json untuk SPA routing).Database & Backend Web (Data Persisten): Node.js/Express (TypeScript) + Prisma ORM + MySQL yang dikonfigurasi agar kompatibel dengan TiDB Cloud (koneksi SSL melalui DATABASE_URL). Bagian ini bertugas menyimpan data persisten web di luar sesi permainan langsung, yaitu:Leaderboard & Statistik Pemain (total main, total menang, akurasi jawaban kuis).Riwayat Pertandingan (Match History) (kode room, daftar pemain, pemenang, waktu selesai).Manajemen Bank Soal IT (opsional/sinkronisasi tampilan referensi soal).Jaringan Real-Time (TCP Murni di VPS + WebSocket Bridge):Inti mekanisme permainan berjalan di server TCP Python murni (server.py pada port 5000 di VPS) yang memakai arsitektur multi-thread dengan protokol ULTA/1.0 (length-prefix framing 4 byte Big-Endian + payload JSON UTF-8).   Karena browser tidak bisa membuka soket TCP mentah secara langsung, frontend React terhubung menggunakan WebSocket (wss:// lewat env VITE_WS_URL) ke layanan WebSocket Bridge (ws_bridge.py di VPS) yang menerjemahkan pesan JSON WebSocket menjadi frame TCP murni ke server utama secara real-time.   Prinsip Authoritative Server: Frontend dilarang menghitung kocokan dadu, posisi baru, efek ular/tangga, timer, atau kunci jawaban soal. Frontend hanya mengirim niat aksi pemain ke server dan merender ulang tampilan berdasarkan event yang dikirim server.   2. Mekanisme & Aturan PermainanKapasitas: 2–5 pemain per room menggunakan kode room acak 6 karakter.   Representasi Papan: Data papan dari server berupa array 1 dimensi berisi 100 petak (indeks 1–100) yang diacak setiap game (8 ular, 8 tangga, 10 petak soal, sisanya normal; petak 1 dan 100 selalu normal). Di frontend, petak ke-n dikonversi ke grid visual 10×10 zig-zag (petak 1 di kiri bawah, petak 100 di kiri atas):   baris = Math.floor((n - 1) / 10) (0 = baris paling bawah)   kolom = (n - 1) % 10, lalu jika baris % 2 === 1, balik arah: kolom = 9 - kolom   Jenis Petak & Efek:NORMAL: tidak ada efek tambahan.   SNAKE (to < n): pemain turun ke petak to.   LADDER (to > n): pemain naik ke petak to.   QUESTION: server mengirim soal pilihan ganda IT (A–D); jika benar pemain maju sesuai dadu bonus, jika salah atau waktu habis pemain mundur sesuai dadu bonus.   Aturan Giliran & Batas Waktu:Banyak pemain diperbolehkan menempati petak yang sama.   Dadu 6 mendapatkan giliran tambahan.   Batas waktu melempar dadu: 10 detik (jika habis, server melempar dadu otomatis).   Batas waktu menjawab soal: 20 detik (jika habis/AFK, dianggap salah).   Jika pemain terputus di tengah game, statusnya menjadi offline, gilirannya dilewati, dan game tetap berjalan.   3. Spesifikasi Protokol Komunikasi (ULTA/1.0 — Flat JSON)Seluruh komunikasi WebSocket antara React dan WebSocket Bridge menggunakan objek JSON flat (tanpa pembungkus "payload"), dengan field wajib type dan seq (nomor urut menaik untuk pesan dari client).   Aturan Koneksi Wajib di ClientBegitu koneksi WebSocket terbuka (onopen), client wajib segera mengirim HELLO (server memutus koneksi jika tidak menerima HELLO dalam 5 detik).Client wajib menjalankan heartbeat otomatis dengan mengirim {"type": "PING", "seq": <n>} setiap 7 detik agar tidak terputus oleh batas heartbeat timeout server (20 detik).   Pesan Client → ServerHELLO: { "type": "HELLO", "seq": 1, "name": "NamaPemain" }   CREATE_ROOM: { "type": "CREATE_ROOM", "seq": 2, "max_players": 4 } (nilai 2–5)   JOIN_ROOM: { "type": "JOIN_ROOM", "seq": 3, "room_code": "5C0315" }   READY: { "type": "READY", "seq": 4 }   START: { "type": "START", "seq": 5 } (hanya host)   ROLL: { "type": "ROLL", "seq": 6 } (hanya saat giliran sendiri)   ANSWER: { "type": "ANSWER", "seq": 7, "q_id": "q_01", "choice": "B" } ("A"/"B"/"C"/"D")   PING: { "type": "PING", "seq": 8 }   LEAVE: { "type": "LEAVE", "seq": 9 }   RECONNECT (opsional): { "type": "RECONNECT", "seq": 1, "token": "..." }   Event Server → ClientWELCOME: { "type": "WELCOME", "seq": 1, "player_id": "...", "token": "..." } (simpan player_id & token di state/sessionStorage).   ROOM_STATE: pembaruan daftar pemain, status ready/online, host, dan room_code/code di lobby.   GAME_START: data board (100 petak beserta jenis & targetnya) dan urutan giliran pemain (order/players).   TURN: { "type": "TURN", "player_id": "...", "deadline": 10 }.   MOVE: { "type": "MOVE", "player_id": "...", "dice": 5, "from": 1, "path": [2,3,4,5,6], "effect": "NORMAL", "to": 6 }.   QUESTION: disiarkan ke semua pemain dengan teks soal, opsi A–D, q_id, player_id, dan deadline tanpa kunci jawaban. Hanya pemain sesuai player_id yang bisa mengklik jawaban; pemain lain melihat status "sedang menjawab".   ANSWER_RESULT: hasil evaluasi soal (player_id, bonus_dice, to). Catatan khusus: field correct hanya dikirim kepada pemain yang menjawab, sedangkan pemain lain sengaja tidak menerima field correct dan menyimpulkan hasil dari perubahan posisi.   PLAYER_STATUS: perubahan status koneksi pemain (online/offline/left).   GAME_OVER: { "type": "GAME_OVER", "winner": "...", "ranking": [...] }.   PONG: balasan heartbeat PING.   ERROR: { "type": "ERROR", "seq": ..., "code": 403, "message": "..." } (tangani kode 400, 401, 403, 404, 408, 409, 413, 429, 500 dengan notifikasi toast yang jelas).   4. Fitur & Halaman Website yang Harus DibangunHalaman Utama (Landing & Entry):Form input nama pemain, pilihan Buat Room (slider/selector 2–5 pemain) dan Gabung Room (input kode 6 karakter otomatis uppercase).   Indikator status koneksi ke server WebSocket (Connected / Connecting / Disconnected) beserta tombol reconnect.Akses cepat ke halaman Leaderboard dan Riwayat Pertandingan (mengambil data dari API Prisma/TiDB).Halaman Ruang Tunggu (Lobby):Menampilkan kode room 6 karakter berukuran besar lengkap dengan tombol Salin Kode.Daftar pemain dengan badge warna pion unik, label Host, status SIAP / BELUM SIAP, serta indikator Online / Offline.   Tombol Saya Siap (READY), tombol Mulai Game (START) yang hanya aktif untuk host saat minimal 2 pemain bergabung dan semuanya siap, serta tombol Keluar Room (LEAVE).   Arena Permainan (Main Game Screen):Papan Ular Tangga 10×10 Zig-Zag Interaktif: Menampilkan nomor petak, garis/ikon visual penghubung untuk ular (SNAKE) dan tangga (LADDER), ikon khusus petak QUESTION, serta pion pemain berwarna cerah yang tersusun rapi meski berada di petak yang sama. Animasikan pergerakan pion mengikuti array path dari event MOVE.   Panel Kontrol Giliran & Dadu: Menampilkan nama pemain yang sedang aktif, countdown progress bar 10 detik, animasi dadu 1–6, dan tombol Lempar Dadu (ROLL) yang aktif khusus saat giliran pemain sendiri.   Modal Kuis IT (QUESTION): Muncul otomatis saat pemain mendarat di petak soal dengan countdown 20 detik, tombol pilihan A–D bagi pemain yang bertugas menjawab, dan tampilan mode penonton ("[Nama] sedang menjawab soal...") untuk pemain lain.   Panel Log Kejadian Real-Time: Riwayat singkat giliran, efek ular/tangga, hasil kuis, dan notifikasi jika ada pemain yang putus koneksi.   Layar Kemenangan (GAME_OVER) & Sinkronisasi Database:Menampilkan pemenang, papan peringkat akhir, tombol kembali ke lobby/beranda, serta otomatis mengirim ringkasan hasil pertandingan ke backend API (Prisma + MySQL/TiDB) untuk memperbarui Leaderboard dan Match History.   Halaman Leaderboard & Riwayat Pertandingan:Tabel peringkat pemain berdasarkan jumlah kemenangan dan total pertandingan, serta daftar histori match terakhir dari database TiDB Cloud.5.
